# Deployment — Neon + Render + Vercel

Target: **DB on Neon**, **API on Render** (Docker), **Web on Vercel**.

Deploy order matters because of the cross-domain cookie + CORS handshake:

```
1. Neon DB  →  2. Render API  →  3. Vercel Web  →  4. point API's CORS at the Web URL  →  redeploy API
```

---

## 0. Push to GitHub

```bash
cd hotel-booking
git init
git add .
git commit -m "Migrate to Next.js + NestJS + Prisma/Postgres monorepo"
git branch -M main
git remote add origin https://github.com/<you>/hotel-booking.git
git push -u origin main
```

---

## 1. Neon (Postgres)

1. Create a project at https://neon.tech → it creates a database.
2. Copy **two** connection strings from the dashboard:
   - **Pooled** (host contains `-pooler`) → this is `DATABASE_URL`.
   - **Direct** (no `-pooler`) → this is `DIRECT_URL` (used for migrations).
   Both end with `?sslmode=require`.

> Prisma uses `DATABASE_URL` at runtime (pooled) and `DIRECT_URL` for
> `migrate deploy` (direct). Both are already wired in `schema.prisma`.

---

## 2. Render (NestJS API, Docker)

**Option A — Blueprint (recommended):** Dashboard → **New → Blueprint** → select
the repo. Render reads `render.yaml`. Then fill the `sync:false` vars:

| Env var | Value |
|---|---|
| `DATABASE_URL` | Neon **pooled** string |
| `DIRECT_URL` | Neon **direct** string |
| `CORS_ORIGINS` | *(temporary)* `http://localhost:3001` — update in step 4 |
| `SEED_ADMIN_EMAIL` | your admin email |
| `SEED_ADMIN_PASSWORD` | a strong password |
| `JWT_SECRET` | auto-generated by Render |

**Option B — manual:** New → **Web Service** → Docker → Dockerfile path
`apps/api/Dockerfile`, Docker context `.`, health check `/api/v1/health`, add the
same env vars.

On deploy, the container runs `prisma migrate deploy` then starts. **Seed once**
from the Render **Shell** tab:

```bash
pnpm --filter @repo/api exec prisma db seed
```

Note your API URL, e.g. `https://hotel-api.onrender.com`.

> Render's free tier sleeps after inactivity — the first request after idle is slow (cold start).

---

## 3. Vercel (Next.js Web)

1. **New Project** → import the repo.
2. **Root Directory** → `apps/web`. (Vercel auto-detects Next.js and the pnpm workspace.)
3. **Environment variable**:
   - `NEXT_PUBLIC_API_URL` = `https://hotel-api.onrender.com/api/v1`
   (`NEXT_PUBLIC_*` is baked in at build time — changing it later needs a redeploy.)
4. Deploy. Note your web URL, e.g. `https://hotel-web.vercel.app`.

> If the build can't resolve `@repo/types`, set Install Command `pnpm install`
> and Build Command `pnpm --filter @repo/web build` with Root Directory = repo root.

---

## 4. Close the loop (CORS + cookies)

1. In **Render**, set `CORS_ORIGINS` = your Vercel URL (e.g.
   `https://hotel-web.vercel.app`) and **redeploy** the API.
2. Leave `COOKIE_DOMAIN` **empty** — the auth cookie is set host-only on the API
   domain, with `SameSite=None; Secure`, so the browser sends it on cross-site
   requests to the API. (Both ends are HTTPS, which `Secure` requires.)

### Cross-domain auth checklist
- [ ] API and Web are both HTTPS (Render + Vercel both are) ✔
- [ ] `CORS_ORIGINS` on Render exactly matches the Vercel origin (no trailing slash)
- [ ] API CORS has `credentials: true` (it does) and web uses `withCredentials` (it does)
- [ ] `NODE_ENV=production` on Render (so the cookie is `SameSite=None; Secure`)

---

## 5. Smoke test

```bash
API=https://hotel-api.onrender.com/api/v1

curl $API/health                         # {"status":"ok",...}
curl $API/rooms                          # seeded rooms
curl -i -X POST $API/users/auth/cookie/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"admin@hotel.local","password":"Admin12345"}'   # Set-Cookie: accessToken=...
```

Then in the browser: open the Vercel URL → log in → confirm the session sticks
(network tab shows the `accessToken` cookie going to the API). Try an admin page
and a booking end-to-end.

---

## Redeploys & migrations
- New migration locally: `pnpm db:migrate` → commit the `apps/api/prisma/migrations` folder → push.
- On deploy, the API container runs `prisma migrate deploy` automatically, applying any new migrations to Neon.
